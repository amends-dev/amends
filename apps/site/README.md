# @amends-dev/site

The site at amends.dev: the product on the home page, the published packages on `/packages`, and
their documentation under `/docs`. It is a static [Astro](https://astro.build) site, with
[Starlight](https://starlight.astro.build) for the docs, served from Cloudflare. The package is
internal to this repository and not published to npm.

## Run

From the repository root, after `bun install`:

```sh
bun run --filter @amends-dev/site dev   # http://127.0.0.1:4400/
```

It generates the package docs first, which takes a few seconds, then reloads as pages change. The
site needs no host running.

## Pages

The home and packages pages are Solid components, `src/home.tsx` and `src/packages.tsx`, which
Astro renders to HTML at build time in `src/layouts/Page.astro`; their only scripts apply the
reader's theme and prefetch links. They compose [UI's site sections](../ui/README.md#the-site), and
the docs take their palette and type from UI too: like the other apps, the site defines no styles,
and `bun run check:packages` rejects stylesheets, style elements, and style props here.

What the pages say about packages comes from the repository. `src/catalog.ts` lists every package
under `packages/` and `adapters/` whose manifest is published, with its version, description, and
the contract an adapter implements. The code on the pages comes from the sources the packages'
checks cover: the home page's from an example in a doc comment, and the quick start from the
adapter's README.

## Docs

The written pages live in `src/content/docs/docs`: the overview and self-hosting. The rest is
generated by `bun run generate`, which `dev` and `build` run first, into folders Git ignores:

- `docs/packages/` holds each published package's README as its guide, without its title. A link
  to another published package's README leads to that package's guide, and a link to any other
  file in the repository opens it on GitHub.
- `docs/api/` holds the API reference, which [`@effect/docgen`](https://github.com/Effect-TS/docgen)
  generates from each package's doc comments: a page for each module, by category, and an overview.
  docgen typechecks the examples in doc comments with the repository's TypeScript, so an example
  that stops compiling fails the build.

docgen writes into the package's own `docs` folder, where its examples resolve the package, and the
generator removes it once read; it stops if a package already has one. docgen is pinned at 4.0.0,
whose Effect range the catalog's Effect satisfies. `scripts/markdown.ts` holds the transforms from
README and docgen pages to Starlight pages, which the tests in `test/` cover.

## Build and deploy

```sh
bun run --filter @amends-dev/site build     # the generated docs, then the site in dist/
bun run --filter @amends-dev/site preview   # dist/ as Cloudflare serves it, at port 4400
bun run test --project @amends-dev/site
```

`build` writes the pages, a search index, and a sitemap to `dist/`, and CI runs it. The site is
served from Cloudflare Workers as static assets, configured in `wrangler.jsonc`: unknown paths get
the 404 page, and pages are served at their trailing-slash URLs. To deploy, log in once with
`bunx wrangler login`, run `bun run --filter @amends-dev/site deploy`, which builds and uploads,
and add amends.dev as the Worker's custom domain in Cloudflare.
