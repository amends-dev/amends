Decided on this screen
01A revision with no turn behind it is a person's edit, and it is marked as one. The distinction is the whole reason the history is worth keeping: an agent's change can be traced to a session, and a hand edit cannot, so it has to say so plainly.
02Selecting a revision shows its content, not a diff. The diff is a toggle against the revision before it, because most of the time the question is what does this say, not what changed.
03Archiving keeps every revision and every byte. It stops new ones being written, which the backend enforces by refusing a revision on an archived resource — so the screen removes the affordance rather than letting it fail.
04The content reference is shown because it is immutable and shared: two revisions with the same bytes point at the same reference, and a revision never rewrites the bytes it was written with.
05There is no revert. Restoring an old version means writing a new revision with those bytes, which is what the history should show — a resource's past is never edited to make the present tidier.
