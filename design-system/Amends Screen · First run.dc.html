Decided on this screen
01The environment comes before credentials, because its harness decides what a model can be — and whether one is needed at all. Asking for a key first would demand something a managed-harness agent never uses.
02The model list is filtered twice: by what the harness supports, then by what the workspace has credentials for. Unsupported models are absent; supported-but-unconnected ones are listed and labelled connect provider, because that is a thing you can fix.
03A harness that brings its own model shows one line saying so, with no picker at all. It is not an empty field — there is genuinely nothing to choose.
04Every record is created behind five plain questions. The last screen names all of them, because the moment something breaks you need to know what exists — but not one step asked you to think about a connection id.
05Marking the first task ready is the last step, so setup ends with work starting rather than a settings page. Nothing runs until the agent has capacity, and the screen says so.
