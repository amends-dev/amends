Decided on this screen
01The page composer and the thread composer do different things, and each says which. Writing on the page starts a thread; writing in the panel continues one. Nothing merges two threads because they share the same two participants.
02Replies live in the thread, not the stream. The stream stays a list of openings, so a long exchange about one script cannot bury everything else.
03Every agent reply carries a one-line execution summary you can open. Answering "how are you" still ran a turn, a session and a cost; that is true and quietly available rather than hidden or shouted.
04A message sent while Ada is mid-turn says where it went: into the execution already running, between prompts. It does not start a second one.
05Work can come out of a conversation without leaving it. track as a task creates a task referencing this thread; until somebody does that, nothing here has a status, an owner or a due date.
