Decided on this screen
01Three statuses are separate and all three are shown: the task is held, its attempt is paused, and that attempt's session finished normally. A session completing is not the work being done.
02Attempts are numbered; an agent reply that was not a task attempt is labelled reply · Ada and sits in the thread without a number. Both ran a session — a reply has execution and cost like any other.
03One composer, two modes. While the task is held it opens in answer mode, because answering runs the task-answer workflow and returns the work to ready; sending an ordinary message does not. You can switch, and the label says which one you are about to do.
04Continuing held work says plainly that it starts fresh. The previous sandbox and agent session are gone; only the conversation survives, and the button should not imply otherwise.
05Two kinds of question, told apart by what happened to the work. A task ask pauses the attempt and holds the task; a question asked in conversation does neither, and the card says so rather than leaving you to infer it from a badge that did not move.
06While an agent is mid-turn the composer sends into the running session instead of starting anything, and the button says add to this turn. A message during execution needs no turn of its own.
07The closing message of a turn appears once, inside the turn summary. It is not repeated as a message in the thread.
