Decided on this screen
01Grouping is by what a task is waiting for, not by status. Held and review are both "needs you" because the action is the same size — nine statuses collapse into five groups a person can scan.
02The row carries its attempt count, which triage rows cannot — a task with three attempts behind it reads differently from a fresh one, and that is exactly what you want before opening it.
03Settled groups collapse by default. They are the largest group and the least useful open, so they start shut and say how many are inside.
04Open question: bulk assign. It is drawn here because the backend supports assignment per task, but assigning twelve tasks to an agent at once is a good way to start twelve sessions by accident. Say if you want it gated behind a confirm, or dropped.
