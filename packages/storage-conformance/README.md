# Storage conformance

Test suites for the gateway's storage and signal hub contracts, run by every storage adapter
against itself. Behavior that core relies on is specified once here and checked on each adapter,
so an adapter for another database passes the same tests as the ones in this repository.
A store keeps its workspace's data its own: it refuses any record that names another workspace,
and core relies on that rather than checking each record or fact again.
The [memory adapter](../../adapters/storage-memory/README.md) runs them as the reference
implementation, with no query language behind it.

The package depends on Effect, `@effect/vitest`, core, and the gateway. It has no runtime of
its own: the adapter's harness supplies cryptography and the storage under test.

## Running the suites

An adapter supplies a `Harness`, conventionally in `test/harness.ts`:

| Member        | Meaning                                                                     |
| ------------- | --------------------------------------------------------------------------- |
| `name`        | Names the adapter in suite titles.                                          |
| `available`   | `false` skips every suite, as PostgreSQL does without a server.             |
| `crypto`      | The hosts' cryptography layer.                                              |
| `withStorage` | Runs one test over fresh, empty storage and releases it when the test ends. |

`withStorage` passes the test a `Storage`:

| Member               | Meaning                                                                                                                                                                                                                        |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `connect(options?)`  | Opens another host over the same storage, with its own connection or pool, closed with the test's scope: its storage, directory, and signal hub. `failFast` asks for prompt contention where the adapter would otherwise wait. |
| `discardProjections` | Removes every projected record, live projection version, and checkpoint, keeping logs and read state, as rebuilding projections does before replay. No storage contract performs this.                                         |
| `footprint`          | Counts every stored record, so a test can show that a rolled-back write left none.                                                                                                                                             |

Each adapter test file registers one suite, for example
`Suites.transactions(harness)`. Tests of how one adapter stores data, such as SQL columns,
query plans, and driver failure injection, stay in that adapter's own files beside the
registration.

`Support` holds the fixtures the suites share: identities, bound stores by name, a fixed
clock, and cores, hosts, and gateways over a harness's storage. Their background wakes are
`manualWakes`: a commit's request is accepted and nothing runs, so a suite runs the process it
expects through the gateway, as a host's runner would. Their turn dispatch is
`WorkspaceTurnDispatch.noRunner`, so a suite drives turn execution itself. `Operations` runs single application
operations through a gateway, the way a protocol handler does.
